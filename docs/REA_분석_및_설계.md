# 건반 내비 — REA(리버스 엔지니어링 분석) 및 설계 노트

작성: 2026-10-29 · 목표: 악보를 업로드하면 어디를 쳐야 하는지 시각적으로 보여주고, 반복 연습·템포 조절로 초보자도 따라 칠 수 있는 앱

## 1. 이전 작업(GPT 대화)에서 이어받은 것
- Flowkey를 참고해 Theishter 「Stay Alive」 전용 브라우저 앱을 만들었음: 낙하 노트, 건반 하이라이트, 손 분리, 속도 조절, 마디 반복, MIDI 입력·불러오기, 대기 모드.
- 한계: 한 곡(Stay Alive) 전용이었고, 1–4마디만 눈으로 검증했으며(5–46마디는 미검증), 마이크 인식은 없었음.
- 이번 버전의 방향: **특정 곡 전용 → 어떤 악보든 올리면 동작하는 범용 앱**으로 확장.

## 2. 유사 시스템 분해 (REA)
| 시스템 | 핵심 메커니즘 | 이 앱에 가져온 것 |
|---|---|---|
| Flowkey | 대기 모드(맞는 음·화음을 칠 때까지 기다림), 구간 반복, 한 손 연습, 마이크/MIDI 입력, 악보 보기 | 따라치기(대기) 모드, 구간 반복, 손 분리, MIDI·마이크 입력 |
| Synthesia | 낙하 노트, 멜로디 연습에서 정답 음까지 대기, 손가락 힌트, 악보 표시 선택, MIDI·MusicXML 열기 | 낙하 노트 + 건반, 손가락 번호 배지, MIDI/MusicXML 동시 지원 |
| Soundslice | PDF·사진 스캔(OMR) → 불확실한 곳은 사람에게 확인 → 편집기에서 원본과 나란히 비교, 구간 반복·속도·건반 시각화 | "AI 초안 + 원본 보기" 흐름, 초안임을 분명히 표시, MusicXML로 저장 |
| Simply Piano 계열 | 마이크로 음 인식. 화음·서스테인 페달·잡음·앱 자체 소리 되먹임에 약함 | 마이크는 단음 전용 베타로 한정, 헤드폰 권장, 전자피아노 연결 시 앱 입력음 자동 끄기 |
| homr / Audiveris (오픈소스 OMR) | 사진/PDF → MusicXML. 피아노 큰보표 지원, 오류 존재 | PDF 정확 변환 경로로 MuseScore 4 가져오기(악보 인식) 안내 |

공통 결론: 성공한 앱들은 모두 ① 악보를 **정확한 기호 데이터(MusicXML/MIDI)**로 바꾼 뒤 ② 그 타임라인 위에 **대기·반복·속도·손 분리**를 얹는다. 이미지 인식은 어디서든 "초안 + 사람 확인"으로 다룬다.

## 3. 구조
```
파일 → [파서] MusicXML / MXL(zip) / MIDI / AI-JSON→MusicXML
     → [Song 모델] 노트(midi, 시작·길이, 손, 손가락, 마디) + 템포 맵(초 단위) + 박자 + 화음 단위 step
     → [엔진] 재생 위치, 대기 모드 판정, 구간 반복, 준비 박자, 메트로놈, 점진적 가속
     → [화면] 악보 커서(OSMD) · 낙하 노트(canvas) · 건반 하이라이트(canvas) · "이 건반을 눌러 주세요" 안내
     ← [입력] 화면 건반(멀티터치) · PC 키보드(e.code, 한글 입력 상태에서도 동작) · Web MIDI · 마이크(단음)
```
- 손 구분: 큰보표 1단 = 오른손, 2단 = 왼손. 파트가 여럿이면 평균 음높이로 나눔. MIDI는 트랙 이름(Right/Left) → 트랙 평균 음높이 → 가운데 도 기준 순서로 정함.
- 붙임줄(tie)은 하나의 긴 음으로 합쳐 다시 치지 않게 처리.
- 악보 커서 동기화: OSMD 커서 위치를 (마디 번호, 마디 안 위치)로 바꿔 자체 타임라인과 맞춤(못갖춘마디에도 안전).

## 4. 초보자용 설계 결정
- 첫 화면부터 예제 곡(환희의 송가, 손가락 번호 포함)이 열려 있어 바로 눌러 볼 수 있음.
- 따라치기에서는 칠 음 이름과 손가락 번호를 문장으로 알려줌(예: "오른손 미 3번 · 왼손 도 5번").
- 틀린 음은 빨강, 맞은 음은 초록. 정확도, 틀린 음, 반복 횟수를 보여줌.
- "틀리지 않으면 속도 +5%" 옵션(100%까지)으로 느린 속도에서 시작해 점점 빠르게.
- 음 이름은 도레미 / C D E / 끄기 중에서 고름. 가운데 도에 점 표시.

## 5. 검증 결과 (2026-10-29)
- 자동 테스트(Chromium): 예제 곡 80음/16마디 해석, 따라치기 대기·정답·오답 판정, 구간 반복 1회 순환, MusicXML(못갖춘마디·붙임줄·화음·손가락 번호·템포 80)과 MXL 압축본, 2트랙 MIDI(손 구분·템포 120) 모두 정상. 400px 모바일 화면에서 가로 넘침 없음.
- OSMD 1.8.9 API 실측: 커서 iterator·마디 타임스탬프·커서 요소·마디 좌표 정상. 실측에서 발견한 버그(reset 뒤 iterator가 바뀜)를 수정함.
- 미검증: PDF 렌더링(pdf.js 3.11.174)과 AI 인식은 실제 악보로 아직 시험하지 않음. 전자피아노 MIDI와 마이크는 실제 기기로 확인 필요.

## 6. 한계와 다음 단계
- 도돌이표·D.S./Coda는 펼치지 않고 처음부터 끝까지 한 번만 진행함 → 다음 단계에서 OSMD 반복 정보로 펼치기.
- AI 악보 읽기는 쉬운 악보에서 쓸 만한 초안 수준이고, 「Stay Alive」처럼 음이 촘촘한 편곡은 틀릴 수 있음 → MuseScore 4 PDF 가져오기 → 수정 → MusicXML 경로를 권장.
- 게시된 화면(claude.ai)에서는 브라우저 정책상 MIDI와 마이크가 막힐 수 있음 → E:\건반내비\건반내비.html을 크롬으로 열면 사용 가능(이 경우 AI 읽기는 안 됨).
- 후보 기능: 손가락 번호 자동 추천, 화음 마이크 인식(basic-pitch 등), 연습 기록 저장, 마디 클릭으로 구간 지정 드래그.

## 7. 소리 엔진 교체 (2026-10-29, 사용자 테스트 피드백)
- 증상: 「Stay Alive」를 재생하면 피아노가 아닌 소리, 자동차 경적 같은 소리, 삐 소리가 남.
- 원인: ① 사인파 8개를 더한 합성음이라 길게 끄는 음과 두꺼운 화음에서 오르간·경적처럼 들림. ② 재생할 때마다 나오는 준비 박자와 메트로놈이 사각파 "삐" 소리였음.
- 조치: TimGM6mb 사운드폰트(GPL-2, MuseScore 기본 사운드폰트였음)의 그랜드 피아노 샘플을 SF2 규칙(반복 구간, 볼륨·필터 엔벨로프)대로 단3도 간격 30음으로 미리 만들어 앱에 넣음(MP3, 약 1MB). 음높이 오차는 ±6센트 이내로 확인. 세기에 따른 밝기, 댐퍼처럼 끊기는 소리, 작은 방 울림, 리미터, 최대 56음 동시 발음을 넣음. 메트로놈은 우드블록 소리로 바꿈.

## 8. 실제 피아노 녹음 + 악보 분석 보완 (2026-10-29, 2차 피드백)
요청: 모든 건반을 실제 좋은 피아노 소리로, 그리고 특정 구간에서 박자가 이상하거나 치지 않아야 할 곳을 치라고 하는 문제 해결.

### 소리
- 기본: Salamander Grand Piano V3 (야마하 C5 실제 녹음, 3건반 간격 30음, MIT). 음마다 4~7초로 다듬고 음량을 맞춤(약 1.3MB).
- 선택: 88건반 개별 녹음 세트(piano-mp3, gleitz/midi-js-soundfonts 출처, MIT). 건반마다 자기 녹음을 그대로 재생.
- 두 세트 모두 음높이를 측정해 검증함. 맨 위 옥타브가 약간 높은 것은 실제 피아노의 스트레치 튜닝.
- 설정 → 소리 → "피아노 소리"에서 바꿀 수 있음.

### 악보 분석(AI 읽기)
- 원인 분석
  1. 페이지 통째로 읽어서 해상도가 부족함.
  2. 템포 변화, 8va, 음자리표 변화, 5·6잇단음을 형식에 담을 수 없었음.
  3. 박자 합이 틀린 마디가 그대로 들어가 이후 박자가 밀림.
  4. 놓친 붙임줄 때문에 같은 음을 다시 치라고 함.
- 보완
  1. 오선을 자동으로 찾아 큰보표 한 줄씩 잘라서 읽음. 「Stay Alive」 PDF에서 24줄 모두 정확히 검출(5·5·5·4·5).
  2. 마디별 bpm, 박자표, 조표, 음자리표(rhClef/lhClef), 8va(rh8va/lh8va), 임의 잇단음(tup:[5,4]) 지원. 내부 해상도는 4분음표 = 840.
  3. 마디마다 성부별 박자 합을 검사함. 틀린 줄은 문제를 알려 주고 AI에게 한 번 더 읽게 함. 그래도 넘치면 잘라내고, 모자라면 쉼표로 채운 뒤 "확인이 필요한 마디"로 표시함(배너 버튼, 악보·낙하 노트에 주황색).
  4. 줄 첫 마디 번호를 악보에 인쇄된 번호와 비교해, 빠지거나 겹친 마디를 경고함.
  5. 붙임줄은 1마디 안에서만 이어 붙임(엉뚱한 연결 방지).
  6. AI 초안에서는 앞 화음의 건반을 계속 누르고 있으면 다시 치지 않아도 인정함.
- 아직 남은 한계: AI 읽기 자체의 오류는 0이 될 수 없음 → 표시된 마디를 원본과 비교하거나, MuseScore에서 고친 MusicXML을 쓰는 것이 가장 정확함.

## 9. 3차 피드백: 화음·박자·업스케일·원본 대조 (2026-10-29)
요청: 화음이 어색함, 쳤던 음을 다시 침, 박자가 아직 안 맞음(실제 메트로놈 기준), 업로드 후 업스케일 → 분석 → 원본 일치 확인 기능, 현재 곡과 원본의 일치 여부 판단.

### 재생
- 같은 순간 같은 건반이 두 성부에 겹치면 한 번만 침(소리가 끊기며 어색해지던 원인).
- 음량 균형: 오른손 맨 윗음(멜로디)은 크게, 화음 안쪽과 왼손은 작게, 베이스는 약간 받쳐 줌. 음이 많은 화음은 전체를 조금 줄임.
- 빠르기 표(설정 → 빠르기): 악보에서 읽은 ♩= 표시를 마디별로 보여 주고, 숫자를 고치면 재생·따라치기·메트로놈이 모두 그 빠르기를 따름(수정 내용 저장됨). "빠르기 변화 무시하고 일정하게" 옵션 추가.
- 새 곡을 열면 구간 반복을 자동으로 끔(이전 곡의 반복 구간 때문에 같은 곳을 다시 치는 것처럼 보이던 문제).

### 분석(AI 읽기)
- 업스케일: PDF는 3000px 폭으로 다시 그림. 사진은 3000px로 단계적 확대 + 언샤프 마스크 + 대비·감마 보정. 저해상도(935px) 페이지로 시험해 선명한 결과를 확인함.
- 마디선 기준 분할: 두 단 사이까지 이어진 세로선만 마디선으로 인정(박자표 숫자 오인 방지). 조각 폭 1500px 이하라 AI가 이미지를 줄이지 않음. 넓은 마디는 중간에서 자르지 않음. 줄 끝 빈 여백은 버림.
- 원본 대조(기본 켜짐): 읽은 결과(JSON)와 같은 이미지를 다시 보내 마디마다 일치/불일치를 판정. 틀린 마디는 고친 버전으로 바꾸되, 박자 검사가 나빠지지 않을 때만 반영.
- 일치 보고서: "처음 읽은 그대로 일치 n마디(%) · 고친 마디 · 아직 다를 수 있는 마디". 마디 버튼을 누르면 그 마디를 반복 재생.
- 빠르기는 ♩= 표시가 인쇄된 마디에서만 읽음(accel./rit. 같은 말은 무시).
- 시험: 가짜 AI 응답으로 전체 흐름(업스케일 → 5줄 → 조각 → 읽기 → 박자 틀린 줄 재요청 → 대조 → 보고서)을 끝까지 확인함. 실제 AI 정확도는 실제 악보로 돌려 봐야 알 수 있음.

## 10. 4차 피드백: 마디별 오류 사례 분석 → 그림 대 그림 대조 (2026-10-29)
사용자가 지적한 마디를 원본과 비교한 결과, 모두 AI 판독 오류였고 재생 엔진은 정상이었음.
- 26–27마디 (화음 어색): "8va treble" 구간이고 왼손도 높은음자리표. 마디 안에서 제자리표(♮)가 유지돼야 하는데 초안은 다시 ♭으로 돌아감 → 임시표·옥타브 오류.
- 30마디 (화음 어색): 왼손 16분음표를 8분음표로 읽음 → 왼손이 두 배 느려지고 넘친 부분이 잘려 오른손과 어긋남.
- 33마디 (쉼표인데 침): 원본도 오른손 쉼표 동안 왼손이 낮은 옥타브와 트레몰로를 침. 소리 자체는 맞지만 트레몰로 판독이 부정확할 가능성.
- 38–39마디 (방금 친 음을 다시 침): 16분음표 화음을 붙임줄로 이어 끄는 당김음이 많음 → 붙임줄을 빠뜨렸거나 끄는 음을 한 번 더 적음.

조치
- 그림 대 그림 대조: 앱이 읽은 결과를 OSMD로 실제 악보 그림(마디 번호, 이음줄 묶기, 잇단음 숫자 포함)으로 그려서, 원본 조각과 함께 AI에게 보여 주고 다른 마디를 고치게 함. 글자(JSON) 대조보다 리듬·임시표·붙임줄 오류가 잘 보임.
- "지금 마디 다시 확인" 버튼: 이상하게 들리는 마디에서 누르면 그 줄만 원본 그림과 다시 비교하고, 해당 마디를 집중해서 봄. 새로고침 뒤에는 원본 파일을 다시 고르면 줄 이미지를 다시 만들어 이어서 쓸 수 있음.
- 판독 규칙 보강: 임시표(♮ 포함)는 마디 끝까지 유지, 글자로 쓴 8va는 loco까지, 붙임줄과 이음줄(slur) 구분, 당김음 붙임줄, 트레몰로는 화음으로, 두 손의 꼬리 수(beam)를 따로 세기.
- 버그 수정: 판정 결과가 문자열일 때 JS 기본 함수(String.prototype.fixed) 때문에 "고친 마디"로 잘못 셀 수 있던 문제.
- 시험: OSMD 그림 생성은 사용자 컴퓨터 브라우저에서 실제로 확인함(마디 번호·붙임줄·음자리표 정상). 전체 흐름과 다시 확인 버튼은 가짜 AI 응답으로 확인함. 실제 AI 정확도는 실제 악보로 돌려 봐야 함.
